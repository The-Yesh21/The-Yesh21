🧭 The idea behind everything

I don't build to collect technologies. I build to understand systems.

My loop is simple:

        ┌─────────────┐
        │   OBSERVE   │
        └──────┬──────┘
               ↓
        ┌─────────────┐
        │    BUILD    │
        └──────┬──────┘
               ↓
        ┌─────────────┐
        │    TEST     │
        └──────┬──────┘
               ↓
        ┌─────────────┐
        │    LEARN    │
        └──────┬──────┘
               ↓
        ┌─────────────┐
        │    SHIP     │
        └──────┬──────┘
               ↓
        ┌─────────────┐
        │ REPEAT, BUT │
        │   BETTER    │
        └──────┬──────┘
               └───────────────↺

That philosophy is why my work jumps across AI/ML, full-stack systems, computer vision, embedded hardware, and product engineering.

I am less interested in asking “What can this technology do?” and more interested in asking:

“What problem becomes possible when I connect these pieces?”

🧩 How I think about engineering

A model is not a product.
A UI is not a product.
An API is not a product.
A clever algorithm is not a product.

A product is the whole loop:

input → decision → action → feedback → improvement

That is the kind of engineering I want to get better at.

🌌 One last thought

I don't want to know everything.

I want to become the kind of engineer
who can enter an unfamiliar system,

trace the moving parts,

understand why it behaves the way it does,

change it without breaking everything,

and leave it better than I found it.
